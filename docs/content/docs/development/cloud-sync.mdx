# LLMRoam 登录与云同步（待验收）

本功能位于功能分支，尚需真实账号和双浏览器验收。访客继续使用浏览器本地数据。登录后按账号隔离 IndexedDB；首次登录只有选择“导入并同步”才上传访客数据。退出先停止同步和运行请求，再清除本机专用 API Key 并返回访客空间。网络不可用时保留上次账号本地空间；登录另一账号后使用其独立空间。

凭据复用版本需要先更新配套 LLMRoam，再更新画布后端。画布授权码交换携带 `reuse_authorization=true`，避免改变其他 OAuth 客户端的独立授权行为。令牌交换响应新增 `sub`、`authorization_id`，`expires_in` 表示剩余秒数，已过期但仍可刷新的授权返回 `0`，由画布在账号锁内刷新。`/api/auth/session` 的用户对象新增非敏感 `authorizationId`，供浏览器识别托管密钥所属授权。后端执行 `004_account_credentials.sql` 后按账号集中加密保存上游凭据，浏览器会话仍相互独立；首次迁移使旧本站会话退出，用户重新登录，本地作品不删除。普通退出不撤销共享授权；主动撤销专属密钥会影响同账号其他浏览器。确认失效的本站请求自动退出，限流和服务故障保留会话。

若登录提示“授权服务版本不兼容”，检查 API 的 `LLMRoam OAuth token response invalid` 与 `Canvas OAuth callback failed` 日志。`sub` 必须是非空字符串，`authorization_id` 必须为正整数；缺失或类型错误会拒绝登录，不能自行补造授权 ID。已核对 LLMRoam `v7`、`v8` 发布标签均尚未包含这批响应字段与凭据复用修改，需将配套修改纳入实际发布源码后构建部署；仅在本地修改源码或更新版本号不会更新线上授权协议。诊断日志不包含可用凭据。

后台「系统配置」的 `hidePrivateChannels` 控制私人渠道配置入口，默认关闭，通过公共设置接口下发。它仅控制应用界面与导入行为，不是对浏览器直连第三方模型服务的安全隔离机制。开关开启后仍保留已有本地渠道、私人模型和系统渠道；管理员可继续配置。

后台「系统配置」的 `userCloudStorageEnabled` 默认开启。关闭后暂停所有账号的私有云同步读写和媒体签名操作，返回 `403` 与 `CLOUD_STORAGE_DISABLED`；保留浏览器及云端已有数据。登录、模型调用、WebDAV、公共库和管理员存储维护不受影响。前端只取消独立同步请求，不取消管理或授权请求；刷新设置、页面获得焦点或恢复联网后读取新状态。已经签发的媒体地址按原有效期失效，不能通过开关立即撤销。

教程列表和已保存的教程流程直接存储在服务端 PostgreSQL 的 `canvas_library` 中，封面及示例媒体存储在公共媒体对象存储中，通过 `/api/admin/tutorials`、`/api/library/tutorials` 和公共媒体接口读写，不参与用户私有云同步，也不受 `userCloudStorageEnabled` 影响。浏览器 IndexedDB 的 `workflow_drafts` 仅用于编辑草稿恢复；保存后的教程以服务端版本为准。公开访问仍受发布状态与 `publicContent.tutorials` 控制，管理接口仍校验管理员权限。

## 存储池、迁移与关联数据备份（待验收）

管理员在 `/admin/storage` 管理 S3 兼容和阿里云 OSS 原生存储池。池包含名称、服务端 Endpoint、浏览器 Endpoint、Region、Bucket、对象前缀、写入状态和凭据；S3 可选择 Path-style 寻址。阿里云 OSS 使用 `ali-oss` 的 V4 签名，Endpoint 填写不带 Bucket 前缀的区域地址，例如 `https://oss-cn-hangzhou.aliyuncs.com`，Region 填 `oss-cn-hangzhou`。两种协议都保持私有 Bucket，由后端签名后浏览器直传。

创建 Bucket、访问授权和 CORS 需预先在存储服务配置：允许本站来源的 GET、POST、HEAD 和所需请求头，服务端凭据具备测试、读取、写入及按需删除对象的权限。连接测试仅检查 Bucket 连接，不能替代浏览器直传验收。凭据使用现有 `ENCRYPTION_KEY` 加密，列表与编辑接口不回传；轮换时两项同时填写，留空保留。须妥善保管加密密钥。

新媒体可指定默认池或在允许写入的池之间等权轮询；上传预留一经创建便固定落池，不因重试或策略改变而自动切池。停止写入不影响历史读取。无可用池时上云失败并保留本地数据。已有媒体、备份或任务引用时禁止删除池和修改位置；删除空池配置不删除 Bucket，删除默认池后需重新指定默认池。用量仅统计本项目登记数据，不代表厂商 Bucket 总容量。

`005_storage.sql` 增加池、分配策略、媒体归属、维护任务和备份清单。API 首次初始化若有完整的六项 `S3_*` 配置，会导入默认池并关联现有媒体；没有完整配置则初始化为空池，登录和后台仍能启动。初始化完成后环境变量不再覆盖后台配置，也不会因后来补全变量再次自动导入；使用后台新增池。升级前备份 PostgreSQL 和现有对象，应用迁移后再启动对应前端。本地开发库已在备份后应用此迁移，真实服务功能仍待验收。

全站同时运行一个维护任务，使用数据库锁跨实例协调，每次传输一个对象；任务记录和明细持久化。失败、服务关闭或数据库执行连接中断后保留进度，由管理员手动继续，不增加自动重试、业务超时或媒体大小限制。页面通过刷新读取进度，关闭页面不停止任务。

- 迁移：先把默认写入池切到其他池，目标池需允许写入；创建任务后源池停止新上传。有效预留需完成或过期后继续，过期未完成预留只移除登记，不扫描、删除其可能残留的对象。迁移未完成（含失败）时源池不能重新开启写入；续行会再次核对源池已停止写入及目标池可写。每个已完成媒体流式复制，校验源和目标实际大小与 SHA-256 后切换索引，媒体 ID 与业务引用不变。源副本保留，待签名有效期结束且没有在线或其他未完成任务引用时，使用独立清理操作删除。
- 手动备份：保存源池已完成媒体及引用这些媒体的私有业务记录、公共库条目、相关 Logo 引用；自动补齐所选记录的跨池媒体依赖。先生成一致数据库快照，再复制到目标池专属前缀并写入带版本、归属和校验信息的清单。目标媒体和清单都校验通过才标记可恢复；备份单独计量，不占用户在线配额。
- 恢复：校验备份清单并预览冲突，默认仅补缺失项；墓碑视为现有记录，覆盖和 Logo 替换须明确选择。备份中的全部媒体恢复至目标池，已有相同内容的媒体也会切换到恢复副本，账号归属和媒体 ID 不变。检查归属、内容身份、所选修订和配额后才在事务内应用在线变化；私有记录分配新的同步修订，公共内容恢复为未发布并脱离原远程来源。预览后修改过的记录需重新预览。恢复不会创建不存在的用户账号。
- 删除备份：创建独立维护任务，仅删除该备份专属媒体和清单，不删除在线对象。迁移及备份的任务历史仍参与池引用检查。

此功能提供媒体及关联数据恢复，不包含无媒体关联的纯文本记录、OAuth 凭据、整站数据库或完整系统配置；不能代替 PostgreSQL 与对象存储的运维备份。未引用媒体、失败恢复副本和未登记对象仍不自动回收。

## 默认边界与失败处理

用户已确认：单媒体 512 MiB，初始每账号 2 GiB（记录 JSON、已完成媒体及未过期上传预留；后台系统默认值及个人额度可调整）；授权码及登录流程 5 分钟、单次使用；访问令牌 1 小时；刷新授权和画布会话最长 30 天；媒体签名地址 10 分钟。时间和媒体边界可通过环境变量调整；`USER_STORAGE_BYTES` 用于首次初始化默认额度，初始化后由后台管理默认及个人额度。超限保留本地并显示失败，令牌过期重新登录，上传或下载地址过期后点击立即同步重新申请。JSON 请求受 Fastify 默认 bodyLimit 约束（1 MiB），大型画布超过此值会保留本地并显示失败。

本地保存后 2 秒合并同步；获得焦点或恢复联网时重试，失败不会无限重试。并发修改按基础修订号检测，保留冲突副本；删除保留墓碑，旧设备不能无条件恢复旧记录。云端暂不自动回收未引用的原始媒体，删除记录不会立即释放已上传媒体容量；运维清理前需核对所有账号引用和备份。

## 本地开发

1. 在 LLMRoam 配置下方 OAuth 应用，启动其服务。画布本地回调固定为 `http://localhost:3000/api/auth/callback`。
2. 复制 `server/.env.example` 到 `server/.env`，填写真实配置；用密码管理器或 `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"` 生成独立加密密钥和客户端密钥，不提交 `.env`。两端客户端 ID/Secret 必须相同，两端加密密钥可不同且重启后必须稳定。
3. 启动 PostgreSQL 和私有对象存储。可在首次启动前填全六项 S3 配置导入默认池，也可启动后在后台添加 S3/OSS 池。服务端地址供 API 访问，浏览器地址必须可被用户访问，不能填写 Docker 内部主机名。
4. 在 `server` 执行 `npm ci`、`node --env-file=.env --import tsx src/migrate.ts`、`node --env-file=.env --import tsx src/index.ts`。使用环境变量中的本地 S3 桶时可先执行 `node --env-file=.env --import tsx src/init-storage.ts` 创建桶并配置本站 CORS；该脚本不处理后台新增的池。
5. 在 `web` 执行 `bun install`、`bun run dev`，访问 `http://localhost:3000`。Vite 将 `/api` 转发到 `127.0.0.1:3001`；若只启动静态前端，登录不可用，本地功能仍可使用。

## LLMRoam OAuth 应用注册

在 LLMRoam 管理后台的“身份验证 → OAuth 授权”中注册一个机密客户端，并将回调地址与浏览器来源精确登记：

```dotenv
Name: Infinite Canvas
Client ID: infinite-canvas
Redirect URI: http://localhost:3000/api/auth/callback
Allowed browser origin: http://localhost:3000
Permissions: api_key:read, api_key:write, api_key:reveal, model_inference:use, profile:read, wallet:read
Code / Access / Authorization lifetime: 300 / 3600 / 2592000 seconds
Enabled: on
```

回调地址完全匹配，不支持通配符。生产环境发行者和画布地址使用 HTTPS。授权端点使用标准 `/api/oauth-provider/authorize`、`/token`、`/userinfo`；Canvas 专属模型凭据继续使用兼容的 `/api/oauth-provider/credentials`。权限必须使用已注册应用允许的明确 scope：`api_key:read api_key:write api_key:reveal model_inference:use profile:read wallet:read`。授权页复用 LLMRoam 登录会话，拒绝个人访问令牌代替用户确认；PKCE 必须使用 S256。登录、MFA 和现有安全验证仍在 LLMRoam 完成。

服务端默认使用 `LLMROAM_URL` 拼接 `/api/oauth-provider/authorize` 作为授权页面地址；如果授权页面部署在其他地址，可在 `server/.env` 设置完整的 `OAUTH_AUTHORIZE_URL` 覆盖该默认值。令牌、用户信息和凭据接口仍使用 `LLMROAM_URL`。

测试阶段 `LLMROAM_URL` 和 `OAUTH_AUTHORIZE_URL` 均支持 HTTP；生产部署使用 HTTPS。画布 `PUBLIC_URL` 的非本机地址仍要求 HTTPS。

连接地址应直接使用授权服务实际提供的 HTTPS 地址，避免依赖 HTTP 跳转：301/302 可能将令牌 POST 转为 GET。`ACCOUNT_ID_ORIGIN` 默认等于 `LLMROAM_URL`，参与生成本站账号 ID；已有账号切换连接协议或域名时，应显式保留原来源，例如连接地址改为 `https://www.llmroam.com` 而账号原来源为 `http://www.llmroam.com`，则配置 `ACCOUNT_ID_ORIGIN=http://www.llmroam.com`。该设置只固定账号命名空间，网络请求仍使用新的 `LLMROAM_URL`；不可随意切换到其他身份提供者。

模型请求由浏览器携带专用 API Key 直连 LLMRoam，消耗用户额度。LLMRoam 应用的 Allowed browser origins 是精确来源列表；模型接口需允许 Authorization、Content-Type 及对应 GET/POST/OPTIONS 预检。已有网关/反代不得另行添加宽泛的 CORS 头。原始媒体所在 S3 桶保持私有，运行 `init-storage.ts` 只为画布来源配置 GET/POST/HEAD CORS。

专用 Key 仅存在当前账号的浏览器本地配置；自动添加 LLMRoam 服务商并读取模型，不更改已有模型选择。默认配置导出排除托管服务商，云同步递归去除密钥、密码和缩略图。账户菜单可撤销专用 Key；撤销后需重新授权才能创建新 Key。

## Docker Compose

在仓库根 `.env` 设置 `POSTGRES_PASSWORD`、`S3_ACCESS_KEY`、`S3_SECRET_KEY`（S3 值与 `server/.env` 一致），先填写 `server/.env`。运行：

```sh
docker compose -f docker-compose.cloud.yml up -d postgres s3
docker compose -f docker-compose.cloud.yml run --rm api npm run migrate
docker compose -f docker-compose.cloud.yml run --rm api node --import tsx src/init-storage.ts
docker compose -f docker-compose.cloud.yml up -d --build api web
```

MinIO 镜像从固定版本官方源码校验 SHA256 后构建，保留 AGPL 许可证；初次编译需要网络和 Go 构建缓存。生产可以将 PostgreSQL/S3 配置替换为外部托管服务，并移除对应本地服务与 `depends_on`。API 和数据库不对公网暴露，前端反代 `/api`。对外 TLS 由部署环境提供；先配置好 HTTPS 公开地址再启用安全 Cookie。

备份 PostgreSQL 与 S3 原始对象，同时保管加密密钥。不能仅备份数据库。密钥丢失会导致已有 OAuth 凭据不可解密，应清除会话后重新授权。生产 Compose 全栈部署及真实账号联调仍待验收。

## 管理后台与公共库部署（待验收）

API 启动时按顺序执行 `server/migrations/` 中的幂等 SQL，包括后台表和用户禁用/备注/额度字段；也可先执行现有 `npm run migrate`。备份数据库后再部署。前后端均需仓库 `shared/`，两个 Dockerfile 已包含它；API 依赖安装沿用 `server/package-lock.json`，包含来源 DNS 校验所用的 `ipaddr.js` 与 `undici`。

`/admin` 使用现有 LLMRoam 登录，服务端每个 `/api/admin/*` 请求实时核对管理员角色。本站保存用户禁用状态、备注、额度、公共内容与管理审计，不修改 LLMRoam 角色或余额。默认额度与个人覆盖均在后端执行；降额不删除已存内容，超额后仍允许删除或不增长的写入，前端本地数据保留。

`/api/library/*` 提供已发布且允许展示的提示词、教程、Skill 和素材；来源、人工覆盖、墓碑及同步状态保存在 PostgreSQL，原浏览器来源配置不导入。服务端默认每 30 分钟同步，关闭/每小时/每 6 小时/每天选项在系统配置中维护。来源使用公开 HTTP(S) 与逐跳 DNS 校验；同步失败保留成功数据，下一周期再试，同源通过数据库锁避免重复执行。

公共媒体与账号媒体共用存储池分配策略，通过 `public/` 与账号对象路径区分，并记录各自所属池；无需开放桶匿名读取。上传仍使用原有大小限制、SHA-256 校验与签名有效期。公共媒体入口先检查发布及展示状态，再重定向到对应池的短期签名地址；下架后不再签发新地址，但已经签发的地址可用到现有的 10 分钟有效期结束。用户保存副本时把媒体和封面复制到浏览器本地，后续走账号独立云同步，公共内容下架不删除这些副本。未引用私有/公共对象的回收仍待后续实现。

调用记录由登录用户的浏览器向 `/api/ai-events` 尽力上报，一次逻辑调用使用账号与请求 ID 去重，视频轮询及恢复不新建记录。只记录脱敏文本、参数白名单、媒体类型/数量和实际返回的用量，不记录 API Key、认证头、媒体 base64，也不汇总本地 Agent 对话。未知费用留空；浏览器关闭或上报失败可能留下进行中记录，这些日志不能替代网关账单。

本轮仅完成实现及新增回归用例，未运行测试、构建或语法检查，生产 Compose、真实来源同步、S3、OAuth 与双浏览器操作仍需按[待测试](/docs/progress/pending-test)验收。

## 验收

- 普通页/画布页、手机宽度、深浅主题：指定入口消失，最右侧始终能登录。
- 成功、拒绝、错误 state、过期、重放、恢复会话、退出；模型列表与实际直连调用；手工服务商和模型选择保留。
- 两个浏览器同步画布、素材、生成历史及原始媒体；并发编辑保留副本、删除、断网恢复、上传失败和超额。
- 两个账号互访记录及媒体应被拒绝；访客导入拒绝前不上传，退出及再次授权不残留专用 Key。
- 已执行的自动化检查和仍待真实环境验证的项目见 Pending Tests；不将此分支作为生产完成声明。
